# 飛び出し検知：調整用・評価用の固定区分

固定日：2026-10-05。新しい局所背景比較方式を実装する前に設定。

## 区分

自車スロットル0.2の15記録を、各条件の採用1反復目＝調整、2・3反復目＝評価に分ける。
記録全体を単位とし、同じ記録のフレームや時間窓を双方へ分けない。
RGBとEVSは同じ区分を使う。成績の良し悪しによって記録を入れ替えない。

| 条件 | 調整用 | 評価用 |
|---|---|---|
| 飛び出しなし | `t_0.2-none` | `t_0.2-none_01`, `t_0.2-none_02` |
| 20%・左 | `test_01` | `test_02`, `test_04` |
| 20%・右 | `test_05` | `test_06`, `test_07` |
| 100%・左 | `test_11` | `test_12`, `test_13` |
| 100%・右 | `test_14` | `test_15`, `test_16` |

- 調整用：5記録（飛び出し4、なし1）。
- 評価用：10記録（飛び出し8、なし2）。
- 対応表の根拠は[引き継ぎ資料](rc_popout_presentation_handoff_20260930.md)。方向・反復の対応は、データ側のbench `plan.tsv` と `attempts.jsonl` で照合する。こちらからSSHはしない。
- 機械可読の区分：[development_evaluation_split_v1.json](evidence/rc_popout_20260930/development_evaluation_split_v1.json)。これは区分表であり、既存検知器の `--config` に直接渡す解析設定ではない。

## この区分の位置付け

全15記録の全体統計、初出現時刻、初出現前後の活動量は既に確認している。
従って完全に未見のテストセットではなく、**新方式の調整にこれ以降使用しない内部評価用記録**と位置付ける。
独立した確認には、方式固定後の追加収録が望ましい。

以前、詳しく見る候補として `test_06` と `test_07` を挙げたが、今回の固定区分では評価用とする。
新方式の開発中にそれらの局所波形・ヒートマップを確認して手法を変更しない。
当面の可視化・試行錯誤は調整用5記録に限定する。

## 調整するもの

1. 共通ROI内のタイル別活動量を取り出す。初期候補は32×32画素。
2. タイルの現在値を、そのタイルの過去の活動量・ばらつきと比較する。
3. 周辺領域に共通する増加と局所的な増加を比較し、まとまりを判定する。
4. 背景だけの記録と正例の出現前も評価し、誤反応・見逃し・遅れの関係を見る。

タイル時系列の抽出と局所背景・同じ高さの帯・隣接タイルを使う検知の試作は実装済み。
後者の調整用第1試行は完了したが、RGBの長時間反応とEVSの背景候補が残っており、背景分離を達成したとはいえない。
調整用で分離の見込みがなければ、評価用を開かずに動きの方向など別の特徴を検討する。
既存の全ROI方式と空間最大値方式は比較の基準として残す。

負例はモデル・閾値作成に再使用しており、倍率選択も調整用の正例を確認した後の判断である。

### チューニングの制約

- セッション別、方向別、プロポ設定別の専用閾値は作らない。
- RGB/EVSのスコアの単位は異なるので、閾値まで同じ数値にする必要はない。
- 共通の判定構成・調整手順を使い、各センサで試したパラメータと選択理由を残す。
- 初出現注釈は評価にのみ使う。検知開始のゲートや検知器の背景更新停止時刻に使わない。
- 発進から約1.5秒後だけを検知対象とするなど、撮影タイミングを利用しない。
- 現在より先のデータは使わず、現在の観測窓も過去背景の統計から分離する。
- 自動的な過去背景更新は固定アルゴリズムの一部として評価中も動かしてよい。評価結果を見た人による設定変更とは区別する。
- 持続条件は時間で定義し、RGBの同じフレームを繰り返し判定して証拠を水増ししない。
- 暖機時間、閾値超過の結合、再検知、欠測の扱いも固定する。

## 評価開始前に固定・保存するもの

- コードのGit revisionおよび未コミット差分があればそのスナップショット。
- ROI・投影・校正、同期YAML、注釈の内容とハッシュ。
- タイル寸法、蓄積窓、更新周期、背景履歴長、ばらつきの下限、周辺比較、候補領域・持続条件、各センサの閾値。
- 評価時間範囲、誤反応の定義、見逃しの定義、時間的な対応付けの範囲と手順。
- 検知時刻は必要な入力と持続条件が揃った時刻とし、オフライン処理時間とは分ける。

正例にも出現前の誤反応があり得る。単に「最初の閾値超過＝正しい検知」としない。
RGB初出現より早い反応は、対象位置や直前の非表示フレームを確認して、先行検知なのか背景反応なのかを分ける。
同期の不確かさに比べて小さい差は優劣未確定として扱う。
評価窓・対応付けを評価結果に合わせて変更しない。

## 固定後の実行順序

1. 調整用の最終結果を保存する。
2. 評価用10記録に固定設定で適用する。
3. 飛び出し8記録の候補の対応、見逃し、時刻差、正例の出現前誤反応を全件示す。
4. 飛び出しなし2記録の誤反応数と有効観測秒数を示す。短時間なのでゼロ件を一般化しない。
5. 同じ方式と検知パラメータを静止条件へ適用する。静止条件の既存校正・投影・ROIの違いは明記する。ROIで割る密度などを使い、単純な総数閾値の面積依存に注意する。
6. 自車0.1の飛び出しなし3記録は、固定後の補助確認に使用する。自車0.2の主評価に混ぜない。

静止条件も以前の基準手法を調整した記録であり、独立した未見データとは呼ばない。
評価結果を見て方式を変更した場合、その評価用記録も開発で参照済みとなる。変更前後を区別して保存し、同じ評価結果を未見テストとして報告しない。

## 現在の実施状態

区分表と手順を保存済み。第1段階として[全ROIの逐次変化検知](rc_popout_change_detection.md)を実装した。
調整用5記録の全ROI検知はユーザーが第1・第2試行を実行した。第2試行で候補の長時間保持は改善したが、負例にも複数候補が残った。
[タイル時系列の出力と比較図](rc_popout_tile_activity.md)は、ユーザー実行の5件すべてで成功した。
事後的な局所ピークに出現前後の差があり、[局所変化検知の試作](rc_popout_local_detection.md)へ進んだ。
合成データで因果性・一様増加の抑制・隣接条件などを確認し、ユーザーが局所検知の第1試行を実行した。
負例EVSの候補回数と継続時間は減少したが、RGBは長時間反応が増え、全体候補への統合が対象時刻の判別を妨げる可能性がある。
[保存済み局所状態の監査](rc_popout_local_review.md)で、全体警報中に多数の別ペア反応が始まることと、RGB負例にも162件の独立ペア反応があることを確認した。
RGBの走行中ON率は正例・負例とも約95～96%。候補の統合だけでなく背景分離にも問題が残る。
調整用5件の保存NPZを受領し、[直接解析](rc_popout_development_bundle_analysis_20261006.md)を実施した。元の全10ケースの候補数・時刻・位置を再現済み。
負例から決めた閾値0.25ではEVSは負例0件・正例各1件となった。[受領画像の照合](rc_popout_candidate_visual_review_20261006.md)で4件とも車両輪郭に沿うイベントが候補タイルと重なることを確認したが、背景の寄与や判定に使った過去2 ms窓の検証は残る。
RGBは現行方式と今回試した変更では、背景を抑えつつ4件全てを初出現後250 ms以内に拾う振幅分離ができなかった。
次はこのEVS結果を調整用の比較基準として残し、両センサに共通する背景移動の補償を検討する。設定の確定と評価用の実行はまだ行わない。
[疎な特徴点の背景移動補償](rc_popout_flow_detection.md)を調整用限定で実装した。RGB画像と過去10 msのEVS画像を独立に処理し、同じアフィン残差・隣接ペア・持続条件を使う。合成検証は通ったが、[ユーザー実行の第1試行](rc_popout_flow_trial01_review.md)ではEVSの走行中判定可能率が約1.5～6.0%、RGBは負例で27候補となり、この設定は採用しない。保存済みの棄却理由と候補位置を診断する。
こちらからLinux側のデータや解析結果は変更していない。
